What Red Marten is, who it serves, and the four ideas every design decision answers to.

Red Marten replaces the stack a revenue team stitches together — data provider, sequencer, dialer, analytics, CRM glue — with one platform where AI agents do the work. The four pillars

P—01

Speed is the product

A buying signal decays in hours. Every screen answers "what changed, and what did we already do about it" before it answers anything else.

P—02

Autonomy over assistance

Agents complete work; they don't suggest it. Copy says "Alice booked 14 meetings", never "Alice can help you book meetings".

P—03

Evidence on every claim

No number appears without its source, its window and its delta. Intelligence you can't audit isn't intelligence.

P—04

Quiet ground, one red

Warm bone surfaces, a single red spent only where it means something. The data, charts and canvas are the only things that raise their voice.

Why a marten

The animal

A marten is small, fast and relentless — it out-manoeuvres animals many times its size. That is the promise: a lean team out-executing an enterprise sales org.

The posture

The mark is caught mid-leap, not standing. It is committed to a direction. Every layout inherits that: forward, rightward, no idling.

The trail

The sweep beneath the body is the path already covered — work the agents finished. It is the only part of the mark that ever animates on its own.

Audience

Primary buyer

VP Revenue / Head of Growth at a 50–1,000 person B2B company. Judged on pipeline and CAC. Buys outcomes, not features.

Daily operator

Growth / RevOps / SDR lead. Lives in the workflow canvas and Data Studio. Wants speed, keyboard control, and no surprises in credits.

Verticals

B2B SaaS · Marketing agencies · Recruitment · Consulting · Enterprise sales orgs · Funded startups scaling outbound.

Voice & tone

Words are design material. Same rules for a landing headline and an error toast.

Red Marten speaks like a senior operator briefing you — short sentences, real numbers, no hype, no apology. It never uses the word "revolutionary", never opens an error with "Oops", and never calls an agent "magical". It also never leans on the animal: no "hunt", no "prey", no "pounce" in product copy.

02

The mark

A marten mid-leap over the trail it already covered. Two shapes, one silhouette.

The mark is two closed shapes and one counter — the body caught at the top of a leap, the sweeping trail beneath it, and the eye cut out of the head. Nothing else. It carries at 16 px because the silhouette does all the work: the ear notch, the muzzle taper and the gap between body and trail are the three details that must survive every reproduction.

Asset status. Vectored from the supplied test.png (199 × 192 px) — cream/red field separated, contour traced at 6× with sub-pixel smoothing, then fitted to 39 cubic Béziers across the two shapes. Matches the source at 96.06 % pixel overlap, and is materially smoother than the original, which was pixel-stepped at that size. Supply the master vector when you have it and the curves become authored rather than derived.

Mark motion

One animal, four behaviours. Motion is a system state, never decoration.

The mark already contains its own animation: the trail is the path travelled, so every behaviour is built by moving the trail against a held body. A user learns the vocabulary once on the landing page and then reads it everywhere — splash, auth, dashboard boot, agent thinking, workflow execution.

Leap timing sheet

TrackStartTransformEnvelope
Trail wipe0 msclip rect translateX 0 → 124
Body entry200 mstranslate(−14, 11) scale(.90) rot(−5°) → identity
Wordmark520 msopacity 0 → 1, translateX(−6px) → 0

Trail wipe eases on cubic-bezier(.22, 1, .36, 1) — fast out of the gate, long settle, so it reads as distance covered rather than a bar filling. The body lands on cubic-bezier(.34, 1.56, .64, 1); the 4 % overshoot is the whole illusion, and removing it makes the mark look pasted on. Total 860 ms.

How the wipe works. The trail is clipped by a <rect> inside a <clipPath>, and only that rect is translated — never the path, never a width attribute. Pure transform means it composites on the GPU and behaves identically in every engine. Each instance needs a unique clipPath id; MartenMark generates one with useId().

Motion rules

Rule 01

Only one mark animation is on screen at a time. A thinking agent suppresses the route loader.

Rule 02

Loaders appear only after 400 ms of latency. Below that, show nothing — a flash of loader reads slower than no loader.

Rule 03

Under prefers-reduced-motion, all four resolve to the static mark with the trail fully drawn. No fades, no substitutes.

Rule 04

The body never rotates in a loop and never leaves the frame. Only Leap moves it, and only once.

Rule 05

The trail is never animated independently of meaning. If nothing is loading, the trail is simply drawn.

Rule 06

Nothing scales the mark past 1.04. Beyond that the 1.9 u body–trail gap closes and the silhouette turns to mush.

Signature interactions

Counter roll

KPI values count up from 0 over 900 ms, ease-out, tabular figures so width never jitters. Fires once per mount, never on refresh.

Connection draw

Workflow edges draw with stroke-dashoffset over 420 ms when created; during a run, a 3 px accent dash travels the edge at 40 px/s.

Card lift

Hover raises a card 2 px and steps shadow-2 → shadow-3 in 140 ms. Never scale, never tilt.

Chat stream

Agent replies fade in per line at 60 ms stagger while Scent loops in the avatar slot. Stops the instant the first token lands.

Row reveal

Table results stagger 24 ms per row, capped at 12 rows — beyond that the whole block fades as one.

Skeletons

Sunk-surface blocks with a 1.4 s red shimmer at 5 % opacity. Matched to the exact geometry of the content they replace.

Data language

Charts inherit the palette. Series colour is assigned by position, never by taste.

Red Marten is a reporting product before it's anything else, so the chart system is part of the brand, not a downstream decision. Categorical series run in a fixed order so the same source keeps the same colour on every screen in the product.

Beyond six categories, group the tail into "Other" at Bone 200 #E5D9D2. Sequential ramps run Bone 100 → Marten Red; diverging runs Red ← Bone 200 → Patina.

Chart rules
  • Horizontal gridlines only, at --color-border. No vertical grid, no chart borders.
  • The final data point always carries a filled dot — the eye lands on "now".
  • Area fills at 10 % opacity of the stroke colour. Never gradients.
  • Every chart states its source and freshness in a caption. No exceptions.
  • Semantic colour appears in charts only for deltas, never for series.
  • Empty state shows the axes with a one-line reason, never a blank box.

Design tokens

The contract between this book and the codebase. Components read tokens only.

Tokens ship in three synchronised forms: CSS custom properties for runtime theming, JSON for design-tool sync, and a Tailwind preset so utility classes resolve to the same values. All three are generated from the JSON — never edited independently.

{
  "color": {
    "red": {
      "700": { "$value": "#8A0E0D", "$type": "color",
               "$description": "core, from the logo plate" },
      "400": { "$value": "#CF5F52", "$type": "color",
               "$description": "dark-theme accent" }
    },
    "bone": {
      "50":  { "$value": "#FCF8F5" },
      "150": { "$value": "#EFE6DF",
               "$description": "logo cream — fixed" },
      "900": { "$value": "#1A1614" }
    }
  },
  "motion": {
    "mark": {
      "leap": { "$value": { "duration": 860,
                             "bodyDelay": 200,
                             "ease": "spring" } }

}
Naming convention. --{category}-{role}-{modifier}. Categories: color, brand, font, text, space, radius, shadow, ease, duration, z. A component may never reference a ramp step directly (--color-bone-300) — only a role (--color-border-strong). The one exception is --brand-red and --brand-cream, which are deliberately theme-invariant because the logo plate must not shift between light and dark.

Interaction requirements

Focus

2 px accent ring, 3 px offset, on every interactive element including canvas nodes. Never outline: none without a replacement.

Targets

44 × 44 px minimum on touch. Dense table rows use a 32 px row with a full-row hit area.

State beyond colour

Every status carries an icon or label alongside its colour — node status, sentiment, deltas, badges. Critical where brand red and error red share a hue family.

Motion

prefers-reduced-motion resolves all four mark behaviours to the static mark with the trail fully drawn. No parallax, no autoplay video.

Canvas

The workflow builder ships a full keyboard path: tab to node, Enter to configure, arrows to move, C to connect. A list view mirrors the graph for screen readers.
